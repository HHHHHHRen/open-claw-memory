## Java服务故障排查 - OSSClient资源泄漏

### 现象
- 3台机器中1台CPU暴涨，FULL GC次数暴涨
- Finalizer线程数是其他机器的3倍
- HttpClientBuilder实例6,429个（严重异常）

### 根因
```java
// 错误：每次调用都创建新的OSSClient
OSS ossClient = OSSClientBuilder.create()
    .credentialsProvider(provider)
    .clientConfiguration(clientBuilderConfiguration)
    .region(region)
    .endpoint(endpoint)
    .build();
// 没有shutdown()，依赖finalize()
```

### 修复
- 将OSSClient改为静态单例复用
- 避免每次HTTP请求都创建新的客户端

## Java服务故障排查 - HttpClient SSLContext泄漏

### 现象
- TrustAnchor 118,800个（严重异常）
- SSLContextImpl$TLSContext 2,340个
- SSLSessionImpl 14,406个
- 870个ESTABLISHED连接

### 根因
```java
// protoRequestPost方法中
CloseableHttpClient httpClient = HttpClients.createDefault(); // 每次调用都创建新的！
```

`HttpClients.createDefault()`每次都会创建新的HttpClient实例，包括新的连接池和新的SSLContext。

### 修复方案
```java
// 单例复用
private static final CloseableHttpClient HTTP_CLIENT = HttpClients.custom()
    .setDefaultRequestConfig(RequestConfig.custom()
        .setSocketTimeout(500)
        .setConnectTimeout(500)
        .build())
    .setConnectionManager(new PoolingHttpClientConnectionManager() {{
        setMaxTotal(200);
        setDefaultMaxPerRoute(20);
    }})
    .build();
```

## 排查方法总结

### 关键命令
```bash
# 查看Finalizer队列
jcmd <pid> VM.finalizer_info

# 查看堆中对象统计
jmap -histo:live <pid> | head -n 30

# 查看GC情况
jstat -gccause <pid> 1000 5

# 查看线程栈
jstack <pid> | grep -A 10 "Finalizer"
```

### 典型泄漏模式
1. **OSSClient/HttpClient每次new** → 资源泄漏 → Finalizer堆积 → GC爆炸
2. **SSLContext频繁创建** → TrustAnchor堆积 → 内存暴涨

### 最佳实践
- HTTP客户端必须单例复用
- 连接池配置合理参数（maxTotal/defaultMaxPerRoute）
- 使用try-with-resources确保Response及时关闭
- 避免依赖finalize()做资源清理
