## 一、旅游攻略规划方法论

### 1. 核心流程（6步法）

```
明确主题 → 信息搜集 → 路线规划 → 时间管理 → 预算控制 → 协同执行
```

**明确旅行主题**
- 用一句话写下旅行主线："探索东京街头美食与复古文化"、"海边放空+无计划自由走"
- 后续所有决策围绕这个主线

**信息搜集与整理**
- 平台选择：小红书/马蜂窝（攻略）、穷游/Google Maps（交通）、B站/知乎（文化）
- 结构化整理：用表格分类——"必吃清单"、"避雷酒店"、"必须预约"
- 加标签系统："适合上午"、"拍照点"、"带小孩友好"

**路线逻辑规划**
- 用地图标记所有打卡点（Google Maps、百度地图）
- 分组划日：按地理位置将景点分组，一天一组
- 地铁线串联：用一条主线路串起一整天，避免跨区折返
- 每日 2-3 个核心景点 + 1-2 个可选内容

**时间管理原则**
- 午餐必须有明确安排
- 每两天安排一个慢节奏活动（温泉、咖啡、看展）
- 每日行程结束不宜晚于晚上八点（尤其带长辈/小孩）

**预算细化**
- 吃（早午晚+零食）
- 住（住宿+清洁/押金）
- 行（城市交通+长途转移+接送）
- 游（门票、导览、体验）
- 购（纪念品、特产）
- 其他（SIM卡、保险、应急金）

### 2. 两种旅行模式

**游览模式（效率优先）**
```
往返交通 → 玩几天 → 确定景点 → 定酒店 → 找餐馆 → 排每日行程
```

**度假模式（快乐总量优先）**
```
往返交通 → 定酒店 → 列候选景点/餐馆 → 物品清单 → 灵活安排
```

### 3. 实用技巧

- 用携程地图模式筛选酒店，看价格和位置分布
- 用大众点评地图模式找附近餐厅
- 热门景点提前买票（故宫级别）
- 下载离线地图备用
- 预留自由时间和备选方案（雨天室内活动）

## 二、程序员职业操守（鲍勃大叔《匠艺整洁之道》）

### 核心誓言

> 为捍卫和维护计算机程序员职业的荣誉，我承诺：

1. **不写有害的代码**
2. **代码永远是最好的作品** —— 不让有缺陷的代码累积
3. **提供可重复的证据** —— 每次发布证明代码正常工作
4. **频繁小规模发布** —— 不妨碍他人进展
5. **持续改进** —— 绝不让代码变更差
6. **提高生产力** —— 不做降低生产力的事
7. **确保可替代性** —— 他人能补上我的位置
8. **靠谱预估** —— 数量级和精确度都靠谱，不做没把握的承诺
9. **尊重专业** —— 只尊重有操守、标准、纪律和技能的同事
10. **永不停止学习**

### 实践原则

**童子军军规**
> 代码签入时要比签出时更整洁

**随机善意行为**
- 优化字段命名，增强可读性
- 清理无用代码，减少理解成本
- 调整代码结构，保持灵活性
- 增加测试覆盖率（但不变管理指标）

**关于集成**
- 经常进行小规模发布
- 利用一切机会改进创作
- 无畏地、毫不留情地改进

**团队合作**
- 确保他人能够补位
- 给出靠谱的预估
- 不做没把握的承诺

## 三、服务爹的 checklist

### 写代码时
- [ ] 提供完整可运行的代码（不要漏 .collect() 这种细节）
- [ ] 加上非空判断和异常处理
- [ ] 解释为什么这样写，以及常见坑
- [ ] 提供替代方案（Java 16+ 新特性等）
- [ ] 保持代码整洁，注释清晰

### 做旅游攻略时
- [ ] 先问清楚主题、天数、预算、人数
- [ ] 用地图可视化路线
- [ ] 景点按地理位置分组，避免折返
- [ ] 预留自由时间和备选方案
- [ ] 提供实用信息：开放时间、门票、餐厅推荐
- [ ] 考虑爹是阿森纳球迷，可以结合足球元素（酋长球场朝圣等）
