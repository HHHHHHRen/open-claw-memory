## 技术工作

### 阿里广审SDK接入（核心项目）

**Jar包引入问题：**
- 本地开发用 `mvn install:install-file` 把 `legal-openapi-sdk-1.0.0.jar` 装进 `~/.m2`
- 线上部署时发现 CI/CD 机器没有，编译报错：`Could not find artifact com.alibaba.legal:legal-openapi-sdk`
- **最终方案**：jar 放入项目 `lib/` 目录，`pom.xml` 用 `system` scope + `maven-assembly-plugin` 打 fat jar，这样线上不依赖外部仓库

**SDK使用踩坑：**
- `DefaultLegalClient` 构造参数里 URL 末尾带空格，会 404
- `GetItemScanResultResponse.getContent()` 返回的是 `JSONArray/List<Content>`，不是 `HashMap<String, Content>`，强转会 `ClassCastException`
- 业务ID固定为 `【journey_adx】`

**架构方案（已确认）：**
- 单机部署，不用 Kafka
- 每分钟从 Redis ZSET 取 20 个任务，开 20 个线程处理
- 一天 < 2 万张不同图片，QPS 完全够用
- 重试间隔 60 秒，最大重试 30 次（30 分钟超时）
- 接口5查状态 → RUNNING 塞回 ZSET / DONE 调接口10 → 写 Redis 缓存 7 天
- 风险等级取数组中最大值（HIGH > MEDIUM > LOW > NONE）

### 代码质量提醒
- 用户容易把换行符搞丢，导致 SQL 解析错位（`deep_link` 默认值吃进下一行）
- 建议用 `ScheduledExecutorService` 或 `@Scheduled` 做定时触发，不要用 `while(true)+sleep`
